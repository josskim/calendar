# 오늘 이후 예약 검증

관리자 캘린더의 `오늘 이후 예약 검증` 버튼은 `/admin/inventory-audit` 보고서 창만 연다. 검증은 보고서 화면의 `새 검증 시작`을 누르고 확인해야 시작된다. 기본 범위는 오늘부터 앞으로 5개월이다.

동일 날짜 범위의 완료 보고서가 있으면 새 작업을 생성하지 않고 기존 보고서를 다시 연다. 실행 중에는 `검증 중지`로 검증 작업만 취소할 수 있으며 실시간 예약 동기화 워커는 계속 실행된다.

## 처리 흐름

1. CalApp이 지정 기간의 펜션 예약을 날짜·객실별 기대 상태로 만든다.
2. 검증 항목은 사이트와 월 단위로 워커에 전달한다.
3. 워커는 네이버 주간 화면, 나머지 사이트의 월간 화면을 읽기 전용으로 일괄 수집한다.
4. CalApp이 기대 상태와 실제 사이트 상태를 비교해 정상·중요·확인·오류로 집계한다.
5. 보고서에는 불일치 및 조회 오류만 상세 카드로 표시한다.
6. 사이트별 성공·실패·중지 건수와 로그인 만료, 보안 확인, 시간초과 등의 대표 실패 원인을 요약한다.

이 기능은 외부 사이트의 예약 허용·차단 상태를 변경하지 않는다. 실시간 예약 동기화 이벤트가 있으면 해당 작업을 먼저 처리한다.

## 네이버·야놀자·여기어때 토요일 예외

네이버·야놀자·여기어때는 토요일에 `201호`, `202호` 단독 상품을 의도적으로 닫고 `201+202호` 묶음 상품만 판매한다. CalApp 예약이 없어도 세 사이트의 토요일 단독 상품 관리자 마감은 정상 정책으로 처리한다. `201호` 또는 `202호` 단독 상품이 예약 가능이면 `확인 필요`로 보고한다.

## API

- `POST /api/admin/inventory-audits`: 날짜 범위로 새 보고서 생성 또는 동일 기간 완료 보고서 재사용
- `GET /api/admin/inventory-audits`: 최근 보고서 목록
- `GET /api/admin/inventory-audits/{id}`: 진행률, 요약 및 불일치 조회
- `DELETE /api/admin/inventory-audits/{id}`: 실행 중인 검증만 중지
- `GET /api/worker/inventory-audits`: 사이트·월 단위 검증 묶음 수령
- `POST /api/worker/inventory-audits/{id}`: 일괄 상태 확인 결과 저장

워커 API에는 기존 `INVENTORY_WORKER_TOKEN` 인증이 필요하다.
